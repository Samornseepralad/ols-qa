## สรุปสั้น (Executive Summary)

session "Automate" กำลังรัน eval รอบ after-4 อยู่ (ไฟล์แรกของขั้น 1 เวลา 16:55:44 +07) อีก session หนึ่งได้คำสั่งให้ "แยกเลนทำงานที่เหลือ" แล้วเริ่มรันรอบเดียวกันโดยไม่ตรวจว่ามีเจ้าของอยู่ก่อน มันทำขั้น 0 และ 5 ซ้ำทับไฟล์เดิม และ dispatch agent ขั้น 1 อีก 4 ตัว หนึ่งในนั้นเขียน `baseline/helix.json` ทับเป็นโครงว่าง 318 bytes Automate ส่งข้อความประสานงานมาจึงหยุดทั้ง 4 ตัวได้ภายใน 110 วินาทีหลัง dispatch Automate ตรวจแล้วว่าความเสียหายมีแค่ไฟล์นั้น และรันขั้น 1 ของ helix ใหม่ สาเหตุจริงคือโฟลเดอร์รอบ eval ไม่มีกลไกจองเจ้าของที่บังคับด้วยเครื่อง กฎจาก #0184 เป็นแค่ข้อความ จึงเพิ่มกฎ `RUN_DIR_NOT_CLAIMED` ใน agent-dispatch-guard และสคริปต์ `scripts/claim-run.sh`

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไม `helix.json` ถูกเขียนทับ?** — agent ขั้น 1 ของ session ที่สองเขียนไฟล์โครงก่อนเริ่มงานตาม `BRIEF.md` ลง path เดียวกับ agent ของ Automate
2. **ทำไมมี agent สองตัวทำสกิลเดียวกัน?** — session ที่สองเริ่มรอบ after-4 ทั้งที่ Automate รันอยู่แล้ว
3. **ทำไมเริ่มได้โดยไม่รู้?** — ก่อน dispatch session ที่สองตรวจแค่ว่า helix อยู่ที่ `278b2ff` และสะอาด ไม่ได้ตรวจว่ามี session อื่นถือรอบนี้อยู่
4. **ทำไมไม่มีอะไรบอก?** — โฟลเดอร์รอบไม่มี lock และ `ROUND.md` ไม่มีขั้น "จองเจ้าของ" · `OWNER.lock` ถูกเขียนหลังเกิดเหตุแล้ว และเป็นข้อความอิสระที่เครื่องอ่านไม่ได้
5. **ทำไมกฎจาก #0184 ไม่กัน?** — กฎ `AGENT_BOARD.md:11` เป็นข้อความที่ต้องจำเอง ไม่มีเครื่องบังคับตอน dispatch · root cause: งานที่หลาย session เขียนโฟลเดอร์เดียวกันได้ ไม่มีการจองเจ้าของแบบ atomic ที่ hook ตรวจได้

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `agent-dispatch-guard` ตรวจแค่เนื้อ brief (persist, advisor, lease ของบัญชี) ไม่ได้ตรวจเจ้าของโฟลเดอร์ปลายทาง
- `lane-lease-check` ครอบเฉพาะ lease ของบัญชีล็อกอิน ไม่ครอบโฟลเดอร์ผลลัพธ์
- กฎ #0184 เป็นข้อความ

**ยืนยันแล้วด้วย:** ข้อความตอบกลับจาก Automate: "baseline-p md5 16/16 OK · paired: my independent rebuild is byte-identical, keys equal · baseline/helix.json IS your empty skeleton … re-running step 1 helix"

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- หยุดทันทีที่ได้ข้อความ และส่งรายการไฟล์ที่เขียนพร้อม mtime ให้เจ้าของรอบตรวจ ไม่ลบหรือแก้ไฟล์ของอีกฝ่ายเอง
- ขั้น 5 ใช้สูตรตาม `ROUND.md` และยืนยันก่อนเขียน (สร้างไฟล์ after-3 ได้ตรงทุก byte 16/16) ผลที่เขียนทับจึงตรงกับของเดิมทุก byte

### สิ่งที่ต้องปรับปรุง
- ก่อนเริ่มงานที่เขียนโฟลเดอร์ร่วม ตรวจเจ้าของก่อนเสมอ — ตอนนี้บังคับด้วย hook แล้ว
