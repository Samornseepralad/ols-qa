## สรุปสั้น (Executive Summary)

เธรดหลักคัดลอกไฟล์ baseline 16 ไฟล์ด้วย `SK="a b …"; for s in $SK` บน zsh ซึ่งไม่แยกคำในตัวแปร ลูปจึงวนครั้งเดียว และสร้างโฟลเดอร์ชื่อยาวที่มีช่องว่าง 1 โฟลเดอร์ ส่วนตัวตรวจที่เขียนเองเทียบ `md5` ของไฟล์ที่ไม่มีอยู่ ได้สตริงว่างเท่ากัน จึงนับ "match 2/16" ทั้งที่ไม่มีไฟล์ไหนตรงเลย ตัวเลข 2/16 ไม่ใช่ 16/16 จึงจับได้ทันที ลบโฟลเดอร์ผิดออกแล้วรันใหม่ด้วย array ได้ 16/16 `tools/zsh-split-guard/split_rules.js` มีกฎ 3 ที่จับรูปแบบนี้ได้ตรงตัว แต่ยังไม่ได้ผูกเป็น hook ใน `.claude/settings.json` (คอมเมนต์ในไฟล์: "Not wired into .claude/settings.json yet: adding a hook needs the owner's approval")

## 1. ปัญหา (Problem Statement)

- คำสั่ง: `SK="catch-ai-workflow create-bug-workflow … testing-ticket-workflow"; for s in $SK; do mkdir -p $A4/runs_clean/$s; …` → `cp: …/runs/catch-ai-workflow create-bug-workflow helix …/baseline-p1.md: No such file or directory` แล้วพิมพ์ `md5 match 2/16`
- เงื่อนไขนับ: `[ "$(md5 -q src)" = "$(md5 -q dst)" ]` — ไฟล์ไม่มีทั้งสองฝั่ง ได้ค่าว่างเท่ากัน จึงนับเป็นตรง
- ผลข้างเคียง: โฟลเดอร์ว่าง 1 โฟลเดอร์ชื่อรวม 8 สกิลใต้ `runs_clean/`

**สิ่งที่ควรจะเป็น:** ลูปบน zsh ใช้ array `"${SK[@]}"` หรือ `${=SK}` (#0118) · ตัวตรวจต้องไม่นับค่าที่อ่านไม่ได้เป็นผ่าน (`docs/POSTMORTEM_RULE.md` ข้อย่อย #0003/#0006: ค่าที่อ่านไม่ได้ห้ามเข้าการเทียบ · นับสิ่งที่วัดจริง)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมลูปวนครั้งเดียว?** — zsh ไม่แยกคำในตัวแปร scalar ที่ไม่ได้ใส่เครื่องหมายคำพูด
2. **ทำไมเขียนแบบนั้น?** — เขียนตามนิสัย bash ทั้งที่ Bash tool บนเครื่องนี้รัน zsh (บันทึกไว้แล้วใน #0118, #0140)
3. **ทำไมไม่มีอะไรบล็อก?** — `tools/zsh-split-guard` มีกฎ 3 (`for N in $X`) แต่ไม่ได้ผูกเป็น PreToolUse hook (`grep -n zsh-split .claude/settings.json` = 0 บรรทัด)
4. **ทำไมตัวตรวจนับผิด?** — เทียบสตริงจากคำสั่งที่ล้มโดยไม่ดูรหัสจบ ว่างเท่ากับว่างจึงผ่าน
5. **ทำไมคลาสนี้ยังกลับมา?** — root cause: มาตรการของ #0118/#0140 หยุดที่ "มีตัวตรวจ" แต่ไม่ถึง "บังคับใช้" เพราะการผูก hook ต้องให้เจ้าของงานอนุมัติ และยังไม่มีใครขออนุมัติ

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** zsh-split-guard ไม่ได้รัน (ไม่ได้ผูก) · ไม่มีชั้นอื่นตรวจคำสั่ง shell ในเรื่องนี้ · ชั้นที่จับได้จริงคือเงื่อนไข `-eq 16` ของตัวเลขรวม

## 5. แนวทางการแก้ไข (Fix)

- ลบโฟลเดอร์ผิด และรันใหม่ด้วย `SK=(…)` + `"${SK[@]}"` และนับเฉพาะเมื่อ md5 ไม่ว่าง (`[ -n "$a" ] && [ "$a" = "$b" ]`)

**ยืนยันแล้วด้วย:** `md5 match 16/16` · known-answer ของ guard: `printf '{"tool_name":"Bash","tool_input":{"command":"SK=\"a b\"; for s in $SK; do echo $s; done"}}' | node tools/zsh-split-guard/split_rules.js --hook` → rc=2 · รูปแบบ array → rc=0
